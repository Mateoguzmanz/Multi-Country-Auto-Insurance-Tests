# Review — US-01 (Policyholder and vehicle data form)

Consolidated from the code review performed throughout Phases 6 and 10 (the orchestrator
reviewed every change live as it was built, rather than as a single pass at the end —
this file assembles that record into the project's standard review format).

## Findings

| # | File | Issue | Severity | Resolution |
|---|---|---|---|---|
| 1 | `apps/web/src/app/features/quote/quote-form-page/quote-form-page.component.ts` | `canContinue` was a `computed()` signal reading `FormGroup.valid`, a property that mutates in place as the user types rather than being written through a signal. `computed()` only re-runs when a *signal read* changes, not when a held object mutates — so the Continue button stayed disabled forever, even once the form became genuinely valid. | Important (blocks the core flow entirely) | Found by `angular-builder` itself during its own live verification (inspected the component instance via the browser, saw `form.valid === true` but `canContinue() === false`). Fixed by converting `canContinue` to a plain method, re-evaluated every change-detection pass. Confirmed live by the orchestrator in a follow-up browser session: a fully valid CO form enabled Continue and navigated correctly. Commit `2231c2f`. |
| 2 | `apps/web/src/app/features/quote/quote-form-page/quote-form-page.component.ts` (`legalAgeValidator`) | `new Date('YYYY-MM-DD')` parses the string as **UTC midnight**. Reading it back with local getters (`getFullYear`/`getMonth`/`getDate`) silently shifts the calendar date one day backward in any timezone behind UTC — which includes both of this project's target countries, Colombia (UTC-5) and Chile (UTC-3/-4). Concretely: someone whose real birthday is tomorrow (still legally a minor today) could pass the ≥18 gate today, for any CO/CL user born in the second half of a UTC day. | Important (incorrect enforcement of a stated business rule, in exactly the countries this product targets) | Found by `test-writer` while writing the legal-age boundary unit test ("one day short of 18" unexpectedly returned valid). Fixed by adding `apps/web/src/app/core/formatting/parse-date-only.ts`, which parses a plain `YYYY-MM-DD` string as local midnight instead (falling back to the native parser for anything else, so invalid input still produces `Invalid Date`). Used at this call site and at the pricing rule's driver-age factor (US-02, see that review). Commit `8aa4e2e`. Independently re-run by the orchestrator (`ng test`, 67/67 green) and re-derived the timezone math by hand to confirm the root cause. |
| 3 | `apps/web/src/app/features/quote/quote-form-page/quote-form-page.component.ts` (`retry()`) | The field-load error state's Retry button called `window.location.reload()` — a full page reload to retry a single failed HTTP request, because the foundation service (`CountryContentService`) had no refetch capability yet. | Nit (works, but coarse — wipes any other in-progress state unnecessarily) | Flagged explicitly by `angular-builder` rather than left silent. Fixed by the orchestrator: added `refetchFormFields()` (and matching methods for plans/terms) to `CountryContentService`, wired `retry()` to call it instead. Commit `2231c2f`. |

## Coverage notes

- The misconfigured-`select` state (a `select` field with no configured options) has no
  real trigger in the current CO/CL seed data, so it was never exercised through a live
  click-through — only unit-tested (`quote-form-page.component.spec.ts`) and verified by
  code inspection. Not a defect; a documented testing-surface limitation of the seed
  data, not the implementation.
- `legalAgeValidator` and the generic `min`/`max`/`pattern` validator mapping
  (`buildValidators`) are unit-tested at their exact boundaries (exactly 18 today vs. one
  day short; configured `min`/`max`/`pattern` violations and their resolutions).

## Verdict

**Approved with changes** — both Important findings were real correctness bugs, not
test artifacts, and both are fixed and verified (unit tests + live browser + e2e). The
Nit was fixed for cleanliness, not because it blocked anything.
